# Public document brand system

Use this system for Obenan proposals, performance reviews and sales presentations. It governs
documents, not the product interface or website implementation.

## Brand character

Obenan should feel calm, exact and premium. The work is evidence-led, never visually noisy.
Every page should communicate one idea, one proof object and one useful next step.

## Typography

- Primary typeface: Helvetica Neue.
- Fallbacks: Helvetica, Arial, sans-serif.
- Headlines and subheads: Light or weight 300.
- Body: Regular or weight 400.
- Labels: weight 500, uppercase only for short navigation or evidence labels.
- Use tabular numerals for metrics and pricing.
- Never shrink body copy below a comfortable print size to solve overflow. Edit the copy.

## Core colors

| Role | Value | Use |
|---|---|---|
| Ink | `#0F0F14` | Headlines, body, dark covers |
| Paper | `#FFFFFF` | Main page background |
| Soft | `#F7F7F7` | Quiet panels and cards |
| Soft 2 | `#F0F0F0` | Alternate section ground |
| Hairline | `#E6E6E6` | Rules and borders |
| Secondary | `#666666` | Supporting copy |
| Quiet | `#999999` | Metadata and captions |

Choose exactly one accent per document from the approved dark palette:

| Accent | Value |
|---|---|
| Aqua | `#00BDEA` |
| Blue | `#598AFF` |
| Violet | `#9289F9` |
| Pink | `#FE5B9A` |
| Red | `#FF4A4A` |
| Yellow | `#FFAD4A` |
| Green | `#1BC47D` |

Do not use pure black. Do not use decorative gradients. The supplied logo may retain its own
canonical spectrum treatment.

Existing-client review exception: `EXISTING_CLIENT_REVIEW.html` follows the operator-selected
reference with orange `#F67900` and 600-weight finding/number typography. This is confined to
the review template; other deliverables retain the palette and light headlines above.

## Composition

- One focal point per page.
- Use generous margins and whitespace.
- Align text, numbers and rules to a simple grid.
- Prefer flat surfaces, hairline borders and small radii over heavy shadows.
- Use dark pages sparingly: cover, section break or one intentional proof moment.
- Let data carry visual weight. Do not decorate weak evidence.

## Data display

- Show the baseline, comparison window, geography and source.
- Prefer position and length: bars, timelines, tables, ledgers and small multiples.
- Avoid gauges, doughnuts, pies and hue-only magnitude encoding.
- Label estimates, assumptions and inferences directly.
- Include an evidence note or companion evidence file for every customer figure.

## Voice on the page

- Headline: the customer outcome or finding.
- Supporting line: why it matters.
- Proof: a measured fact, source or observed gap.
- Next step: one concrete action.
- Avoid generic technology slogans and decorative “AI” language.

## Accessibility and print

- Keep contrast strong and never rely on color alone for meaning.
- Use visible focus treatment in interactive HTML.
- Provide a text label for every icon and status.
- Respect reduced-motion preferences.
- Render at A4, 100% scale, and inspect every exported page before handover.

## Boundaries

This public guide contains no product code, private design files, account data or security
observations. If a task requires those, route it internally rather than adding them here.
